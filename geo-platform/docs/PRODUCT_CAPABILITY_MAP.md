# GEO Platform 产品能力地图

状态：ACTIVE
日期：2026-08-12

## 产品定位

GEO Platform 是一个中文操作型工具，核心回答一个业务问题：

```text
AI 在回答目标用户问题时，为什么没有稳定露出或推荐我们的品牌，以及我们下一步应该改什么、怎么验证。
```

它不是通用 BI 看板，而是一个证据驱动的 GEO 优化闭环：

```text
监测总览 -> 决策诊断 -> 最终策略 -> 发布确认 -> 固定复测 -> 效果结论
```

## 导航模型

### 业务闭环

`监测总览`

- 作用：展示项目当前观察状态。
- 回答：品牌是否出现、是否被明确推荐、引用来源是否完整、采集质量是否可信。
- 不负责：产出最终策略或宣称优化效果。

`决策诊断`

- 作用：解释单个问题的回答结构和 AI 决策信号。
- 回答：用户意图是什么、AI 采用了哪些选择标准、有没有品牌/方案槽位、引用资料如何支撑回答、目标品牌差在哪里。
- 输出：诊断包，以及可选的 Issue / Action / Experiment 草案。
- 不负责：最终策略审批、外部发布或效果结论。

`最终策略`

- 作用：唯一最终策略出口。
- 回答：基于证据包和诊断草案，哪个策略候选应该被审核、接受、发布、复测和结论化。
- 输出：证据包、策略候选、动作、实验、发布审计、复测记录和人工结论。
- 规则：真实业务效果只能在发布确认、固定复测、数据对比和人工审核后结论化。

### 证据工作台

`引用资料`

- 作用：以最终引用资料为主要证据面进行分析。
- 回答：哪些域名/页面被引用、引用强度如何、平台/内容类型结构如何、哪些页面可能值得优化。
- 边界：检索候选只作为重合度旁证，不是严格漏斗，也不能当作最终引用的分母。

`证据标注`

- 作用：审核主张、引用片段、URL 身份和段落对齐证据。
- 回答：AI 回答中的主张是什么、引用页面是否抓取成功、回答片段和引用原文能否对齐、哪些证据需要人工确认。
- 边界：产出已审核证据，不产出最终策略。

`采集记录`

- 作用：查看每条原始采集样本。
- 回答：每次采集的问题、状态、原答案、引用详情、原始证据文件和解析质量。
- 边界：这是审计轨迹和调试层，不是分析结论页。

### 系统配置

`问题配置`

- 作用：维护项目、问题、问题组和采集批次。
- 规则：一个问题就是一个用户问题。采样次数表示独立采集记录，不表示总体市场概率。

## 当前能力边界

- 平台优先分析最终引用资料和回答正文。检索候选是辅助证据，可能不完整。
- 当回答里没有品牌时，页面应直接显示“当前没有品牌推荐”，再判断答案内容里是否仍存在品牌露出机会。
- `决策诊断` 可以生成草案，但生成草案不等于最终策略。
- `最终策略` 是唯一策略确认入口，策略候选必须在这里进入实验闭环。
- `引用资料` 和 `证据标注` 支持策略判断，但不独立给出业务最终动作。
- 所有用户可见名称、警告、空状态和操作按钮必须使用中文，因为目标操作者不应依赖英文理解系统。

## 建议下一步产品工作

1. 继续把 `决策诊断` 简化成三个操作区：原答案、引用资料、怎么做。
2. 从已生成的诊断草案增加明显的“进入最终策略”跳转，并关联对应 Issue / Action / Experiment 编号。
3. 把 `引用资料` 当前写死的证据包 `#7` 改成可按项目和问题选择。
4. 让 `最终策略` 显示完整状态路径：
   `候选 -> 已确认 -> 执行中 -> 复测中 -> 已结论`.
5. 为所有仍直接展示的后端枚举补齐中文状态字典。
6. 增加完整操作路径冒烟测试：
   `选择问题 -> 生成诊断 -> 创建草案 -> 审核策略`.
