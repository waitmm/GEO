# GEO Platform 1.0 产品范围与交付基线

版本：1.0 文档基线 2026-09-30。用途：产品定义、开发拆分、验收和项目跟踪。作者：依据本轮用户决策整理。读者：产品负责人、开发/Codex、验收人员。

## 文档成熟度

产品方向及关键约束来自本轮已确认讨论。本包把这些约束展开为可实施的功能行为、字段和验收场景；这些具体展开是本次执行基线，不冒充用户逐项审批过的已有规范。未核查仓库实现、接口名称、数据库结构和部署状态，相关事项统一进入 M0 代码核查；不因此要求重新讨论产品方向。

当前文档交付状态为“可开展代码核查与任务落地”，不表示软件已实现或已验收。所有实现任务和测试结果初始均为未完成/未运行。源资料为本轮上传的架构文本及随后冻结的修正意见，不引用早期项目状态作为当前事实。

## 产品目标与用户

面向品牌负责人和内容/增长执行人员，持续观察品牌在 AI 回答中的表现，将答案与引用分析转化为可执行的优化计划和具体交付，在执行后复测结果。

Monitor 回答“现在表现怎样”；Optimize 回答“优先改什么、怎么改”；Validate 回答“执行后观察到了什么”。用户不需要学习内部 Step 编号或依次人工审核才能完成任务。

## 本版用户主路径

1. 创建项目、配置品牌名/别名/官方域名。
2. 添加 Prompt，选择已接入平台与采样次数。
3. 完成采样，查看 Monitor 与覆盖情况。
4. 选择一个 Prompt 及明确样本范围，启动 Optimize。
5. 自动获得诊断、策略、适配渠道、具体稿件及验证条件。
6. 用户在外部执行发布或修改，登记 URL 与时间。
7. 系统核查实际内容并复测，展示同口径 Before/After 与限制。

## 本轮冻结原则

| 决策 | 执行要求 |
|---|---|
| 三段式完整闭环 | 1.0 不停留在监控或诊断报告 |
| 自动化默认 | 知识库和分析型人工审核均非必经前置条件 |
| 有效输入必须有具体行动 | 低匹配、部分事实未知、无知识库不得直接导致成功空计划 |
| 非空不等于任意内容 | 交付须绑定当前 Prompt 的问题与证据，具体到可发布内容或可上线修改 |
| 事实与策略强度分开 | 探索性策略可以执行，不能借此编造产品事实 |
| 资格局部生效 | 限制不合格 claim 或动作，自动改写/替换，不把整条计划清零 |
| 来源与指标可追溯 | 明确 run_ids、Snapshot、ResultVersion、配置和指标版本 |
| 用户纠错为增强 | 支持局部重算，不强制每次分析人工审批 |
| 复用成熟能力 | 先查代码，无旧状态依赖直接复用；必要时提取窄接口 |
| 错误派生状态可重算 | 不为错误中间结果建设长期兼容主链 |

有效输入指已确定品牌/Prompt 分析目标，且存在可消费的有效答案；引用可以缺失、无法获取或匹配低。无合法答案、程序故障、外部调用被拒绝等属于执行失败或待恢复，不能伪造成功。该边界不允许把“没有知识库/没有人工核实”当作输入无效。

## 1.0 范围

包含十五个功能 PRD、共用数据契约、验收矩阵、任务依赖和开工说明。优先支持现有可靠平台；任务记录、版本、项目隔离和可恢复性属于主链质量。界面复用现有技术栈，内部分析能力可以合并编排。

后置：完整知识库/知识图谱、跨项目行业知识学习、复杂综合评分与数字权重、多模型动态路由、规则自动晋升、新采样平台大规模扩展、复杂定时调度、自动发布及广泛 CMS 集成、套餐计费/SSO/完整多人协作扩建、独立 Runtime。已有相关成熟能力可保留，但不能成为本轮新增依赖。

不新增通用硬标准：固定文章字数、固定引用块数、每理由固定同样数量 passages、每个 Prompt 固定写若干文章、所有渠道同样观察天数、两轮正向即有效、官网永久主渠道。实际资源预算可配置且需说明，不得混同语义质量标准。

## 用户界面与交付边界

一级导航保持 Monitor、Optimize、Validate；项目/品牌设置、任务记录和事实纠错作为必要辅助入口。每个 Prompt 详情提供同名三个 Tab。内部基于任务状态异步执行，刷新后继续显示后端进度。可用的旧版本保持可查看，新结果显式替代。

“可发布”是当前版本在事实与内容检查后可交付，不承诺平台一定采纳或推荐改善，也不表示已获得第三方渠道的发布权限。渠道受限时提供适配内容及可操作的替代渠道，不能只留下无法执行的建议。

## 定义完成

软件至少跑通一条真实端到端主路径，同时验证引用支撑充分、引用匹配低和事实部分缺失三类场景。端到端复测不以必须正向提升作为验收条件；它应准确报告实际结果。数据身份、指标口径、具体交付和恢复能力须通过相应验收。

每项任务完成需要对应需求、实现位置、验证证据及剩余限制；没有实测的状态不能写为通过。发布/线上业务修改以用户既有授权范围为准，本文件本身不代替对真实外部操作的授权。
