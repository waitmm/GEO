# 项目与品牌配置

文档编号：PRD-BRD。里程碑：M1。版本：2026-09-30。实现状态：未核查。

业务依赖：基础能力，无前置业务模块。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

用户能够建立分析对象，并明确品牌名、别名与官方域名。品牌配置是实体识别和第一方来源分类的输入，不能直接证明品牌具备某项能力。

本版支持在已有应用框架中管理项目及目标品牌；多人协作、套餐计费、组织权限扩建不列为新增范围。已有登录与隔离能力须保留并核查。

## 页面和主要操作

项目列表：项目名称、目标品牌、Prompt 数量、最近采样时间、运行任务摘要。
项目创建与设置：项目名称、品牌名、别名、官方域名；保存前给出归一化预览。
项目首页：进入 Monitor；设置修改不应打断正在运行的任务。

## 正常流程

1. 填写项目名称与目标品牌，输入可选别名及官方域名。
2. 系统进行去空白、重复项合并和域名归一化；有歧义的别名给出提示。
3. 保存后进入 Prompt 管理；缺少域名可以继续，第一方来源识别显示覆盖限制。
4. 修改配置生成新版本；新任务使用新版本，历史结果保持原配置并允许显式重投影。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| project_id | 系统生成 | 不可跨项目复用 |
| brand_id / canonical_name | 品牌名必填 | 实体身份与展示名分开 |
| aliases[] | 可选 | 不能因字符串命中就认定同一实体 |
| official_domains[] | 可选 | 主域、子域适用范围明确；未知归属不归为第一方 |
| config_version | 系统生成 | 绑定每次分析与指标计算 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| BRD-001 | 同一项目中的品牌识别规则由统一服务消费，不在各页面分别硬编码。 | 保存配置必须可读回且重启后保留。 |
| BRD-002 | 别名是识别线索；对同名普通词须结合上下文消歧，并保留原文位置。 | 系统不得默认所有字符串命中都是品牌提及。 |
| BRD-003 | 域名缺失不阻断采样和优化；相关引用分类标记 UNKNOWN。 | 不得把 UNKNOWN 计为已确认非官方。 |
| BRD-004 | 已有结果不因配置修改静默改变。 | 用户可以从历史结果看到原配置，选择生成新投影。 |

## 状态和异常

创建中、保存成功、保存失败属于表单状态。品牌配置版本为有效或已被新版本替代。删除或清空项目不作为本版新增功能；任何已有删除能力须保留其确认和数据边界。

## 验收场景

| 用例 | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-BRD-01 | BRD-001 | 输入合法品牌名和域名 | 保存并打开项目 | 品牌信息一致，Monitor 空态提示添加 Prompt。 |
| AC-BRD-02 | BRD-003 | 品牌名有效且域名为空 | 保存并添加 Prompt | 允许继续，官方域名引用指标显示配置限制。 |
| AC-BRD-03 | BRD-002 | 别名同时是常用词 | 识别含该词的答案 | 不能仅凭词面强制归入品牌。 |
| AC-BRD-04 | BRD-004 | 已有分析绑定配置 V1 | 修改别名为 V2 | 旧结果仍引用 V1，新任务绑定 V2。 |

各场景初始状态均为 NOT_RUN。验收结果填写到 [验收矩阵](17_验收矩阵.md)，不得因文档齐全就标为通过。
