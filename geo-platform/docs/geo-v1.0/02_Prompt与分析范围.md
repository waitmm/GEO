# Prompt 管理与分析范围

文档编号：PRD-PRM。里程碑：M1。版本：2026-09-30。实现状态：未核查。

业务依赖：BRD。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

用户能够组织监测问题，声明业务重要性和优化目标，并从累计样本中明确选择一次分析所用的范围。意图分类用于组织与目标适用性，不产生未经校准的综合分数。

## 页面和主要操作

Prompt 列表支持搜索、标签和意图筛选、业务优先级、启用状态及样本覆盖。
Prompt 详情包含 Monitor、Optimize、Validate 三个 Tab。
“分析优化”打开范围选择：本次新增、手动选择历史样本、历史加新增；已有分析提供“继续任务”。

## 正常流程

1. 新建或批量输入 Prompt；精确重复项提示复用，语义相似项只提示、不自动合并。
2. 系统建议意图与目标，用户可修改；未分类不阻断采样。
3. 采样持续加入当前 Prompt 的记录池；修改问题文本形成新 Prompt 版本。
4. 进入 Optimize 时选择明确 run_ids；确认界面展示数量、版本、采样时间和平台。
5. 提交后冻结分析范围；后续新增样本不能自动加入该分析。继续旧任务使用原范围。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| prompt_id / prompt_version | 文本必填 | 历史结果保留原文 |
| intent_primary / intent_tags[] | 可自动建议 | 允许多意图，至少有明确主要目标或通用默认目标 |
| business_priority | 默认普通 | 高/普通/低；不等价于算法机会分 |
| target_objective | 系统建议，可编辑 | 如候选推荐、准确描述、步骤完整性 |
| selected_run_ids[] / scope_hash | 提交时必需 | 排序去重后形成不可变范围；空选择不能启动分析 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| PRM-001 | Prompt 版本和采样入口必须可追溯。 | 修改文本不覆盖历史样本对应的问题。 |
| PRM-002 | 固定范围是分析身份组成部分。 | 改变 run_ids 必须创建新分析，不能挪用旧结论。 |
| PRM-003 | 意图只调整目标适用性；事实准确性始终是质量要求。 | 概念问题推荐率为零不能单独触发高机会。 |
| PRM-004 | 已有分析可继续，新增分析按需创建。 | 不得强迫用户为了继续未完成任务重新采样。 |

## 状态和异常

Prompt 为启用或暂停；暂停影响新采样，不删除历史。分析范围草稿在提交前可改，提交后冻结。选择混合平台或混合问题版本时给出分层或不可直接比较提示；不隐藏样本。

## 验收场景

| 用例 | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-PRM-01 | PRM-002 | 已有九个选定 Run | 提交后再增加三个 Run | 旧分析范围仍为九个，新 Run 留在样本池。 |
| AC-PRM-02 | PRM-004 | 已有未完成分析 | 点击继续 | 复用原范围、来源和已完成计算。 |
| AC-PRM-03 | PRM-001 | 已有 V1 样本 | 修改问题并采样 | 新样本绑定 V2；趋势标识版本变化。 |
| AC-PRM-04 | PRM-003 | 概念解释 Prompt 推荐率为零 | 计算机会建议 | 不能仅据推荐率为零判为高机会。 |

各场景初始状态均为 NOT_RUN。验收结果填写到 [验收矩阵](17_验收矩阵.md)，不得因文档齐全就标为通过。
