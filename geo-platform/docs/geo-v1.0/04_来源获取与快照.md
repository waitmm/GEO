# 引用资料获取与来源快照

文档编号：PRD-SRC。里程碑：M1。版本：2026-09-30。实现状态：未核查。

业务依赖：SAM。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

自动获取答案所引用的资料，形成可定位、可复用的正文快照。获取不到或正文匹配低时保留限制，继续利用有效答案、引用观察和可用公开资料规划行动。人工粘贴补录是可选增强。

## 页面和主要操作

来源列表展示 URL、标题、归属平台、引用 Run、获取状态、正文质量与获取时间。来源详情显示冻结正文与 passage 定位。异常项提供重试、补录正文或保留限制继续的操作。

## 正常流程

1. 从选定 Run 构建引用清单，规范化 URL 并保留原始 URL 与锚点。
2. 优先自动抓取；按内容合法性识别正文、登录墙、验证页、空白及不相关内容。
3. 形成不可变 Snapshot 与 passages；同 URL 的新内容产生新 Snapshot。
4. 失败保留原因与可重试入口；系统继续分析可消费部分。
5. 用户补录或系统增补品牌官网资料时，明确来源类型、获取方法和版本，影响新结果而非改写旧结果。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| source_id / original_url / canonical_url | 必需 | 规范化不能丢失实际身份差异 |
| source_role | 必需 | CITED、BRAND_PUBLIC、SUPPLEMENTARY；额外资料不得冒充已被引用 |
| snapshot_id / content_hash / captured_at | 正文快照必需 | 绑定冻结正文 |
| passage_id / offsets | 切分后生成 | 必须定位回同一快照 |
| fetch_status / content_quality / limitation | 系统记录 | 获取成功不等于内容支持答案 |
| provenance / acquisition_method | 必需 | 自动抓取、用户粘贴等明确区分 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| SRC-001 | 引用观察与正文获取分开。 | 正文抓取失败不能抹去答案中已观察到的引用。 |
| SRC-002 | 正文质量不能只靠字数判断。 | 验证页、登录墙不能因长度达标被当作有效证据。 |
| SRC-003 | Snapshot 一经消费不原地替换。 | 来源更新只能形成新版本和受影响计算。 |
| SRC-004 | 来源缺失或低匹配不构成整条优化主链的人工作业 Gate。 | 输出限制及探索行动，不能要求全部人工补录后才生成计划。 |

## 状态和异常

正文状态：PENDING_FETCH、FETCHING、READY、PARTIAL、UNAVAILABLE、REJECTED_CONTENT。保留限制继续是处置方式，不表示正文已 READY。真实网络故障允许恢复；不可消费页面不进入事实支持关系。

## 验收场景

| 用例 | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-SRC-01 | SRC-002 | 抓取返回大量登录说明 | 正文校验 | 标为不可用内容，不切成支持品牌事实的 passages。 |
| AC-SRC-02 | SRC-001、SRC-004 | 答案有引用 URL 但正文不可取 | 继续 Optimize | 引用观察保留，策略仍生成并标注信息限制。 |
| AC-SRC-03 | SRC-003 | 用户提供真实正文 | 保存并重新分析受影响项 | 生成新快照和新结果，旧结果可追溯。 |
| AC-SRC-04 | SRC-001 | 系统获取品牌官网页面 | 参与 Truth 判断 | 标记为额外公开资料，不计入原答案引用数。 |

各场景初始状态均为 NOT_RUN。验收结果填写到 [验收矩阵](17_验收矩阵.md)，不得因文档齐全就标为通过。
