# 引用资料获取与来源快照

文档编号：PRD-SRC。里程碑：M1。版本：2026-10-10。实现状态：原引用准备复用；补充公开来源新增正式入口，隔离集成通过，真实外网验收待授权。

业务依赖：SAM。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

自动获取答案所引用的资料，形成可定位、可复用的正文快照。获取不到或正文匹配低时保留限制，继续利用有效答案、引用观察和可用公开资料规划行动。人工粘贴补录是可选增强。

## 补充公开来源

“品牌资料 → 补充公开资料”接收一个明确公开 URL 与获取授权，复用原公共网络抓取器（匿名、DNS 固定、TLS/重定向检查、最多两次尝试），由现有 release worker 执行。请求幂等、终态不可覆盖；中断保留 INTERRUPTED，不自动重新访问。再次获取必须由用户显式提交新请求，不修改旧版本。

独立保存项目归属、完整正文、获取时间、请求/落地 URL、传输证明与快照 hash，标记 `SUPPLEMENTAL_PUBLIC_SOURCE`。不写入 Citation Manifest，不添加引用记录、不扩大 Contribution 候选范围。无登录、内网抓取或自动访问整个网站。

Optimize 明确选择最多5份已获取版本，创建时固定其全部内容与 hash；PARTIAL仍标不完整，不可冒充完整官方证明。合格的当前品牌官方内容复用现有 SourceClaim/来源核实，费用计入该 Optimize 原独立授权。第三方、不完整、缺证明或超输入上限的内容保留限制，不自动成为品牌事实。事实、原引用、内部粘贴资料分别展示。

2026-10-10：8项专项、87项相关组合、9项恢复/备份检查通过（互有重叠，不加总）；浏览器032308Z通过获取授权、保存、刷新、选版、稿件及归因、编辑复检、三种宽度。1次抓取和7次模型响应均为隔离模拟，真实外调0。完整统一harness和正式迁移另行记录。

## 页面和主要操作

来源列表展示 URL、标题、归属平台、引用 Run、获取状态、正文质量与获取时间。来源详情显示冻结正文与 passage 定位。异常项提供重试、补录正文或保留限制继续的操作。

## 正常流程

1. 从选定 Run 构建引用清单，规范化 URL 并保留原始 URL 与锚点。
2. 优先自动抓取；按内容合法性识别正文、登录墙、验证页、空白及不相关内容。
3. 形成不可变 Snapshot 与 passages；同 URL 的新内容产生新 Snapshot。
4. 失败保留原因与可重试入口；系统继续分析可消费部分。
5. 用户补录或系统增补品牌官网资料时，明确来源类型、获取方法和版本，影响新结果而非改写旧结果。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| source_id / original_url / canonical_url | 必需 | 规范化不能丢失实际身份差异 |
| source_role | 必需 | CITED、BRAND_PUBLIC、SUPPLEMENTARY；额外资料不得冒充已被引用 |
| snapshot_id / content_hash / captured_at | 正文快照必需 | 绑定冻结正文 |
| passage_id / offsets | 切分后生成 | 必须定位回同一快照 |
| fetch_status / content_quality / limitation | 系统记录 | 获取成功不等于内容支持答案 |
| provenance / acquisition_method | 必需 | 自动抓取、用户粘贴等明确区分 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| SRC-001 | 引用观察与正文获取分开。 | 正文抓取失败不能抹去答案中已观察到的引用。 |
| SRC-002 | 正文质量不能只靠字数判断。 | 验证页、登录墙不能因长度达标被当作有效证据。 |
| SRC-003 | Snapshot 一经消费不原地替换。 | 来源更新只能形成新版本和受影响计算。 |
| SRC-004 | 来源缺失或低匹配不构成整条优化主链的人工作业 Gate。 | 输出限制及探索行动，不能要求全部人工补录后才生成计划。 |

## 状态和异常

2026-10-09 访问边界实现：抓取器的 HTTP(S) 连接使用已校验的公网 DNS 地址，TLS 证书必须有效；每次重定向和浏览器可消费子请求沿用同一检查，不携带登录态。私网、凭证 URL、非标准端口、资源大小/时间超限或受限正文保留具体失败/局部状态，不绕过限制。不复用持久化浏览器登录目录。离线工程证据为 `backend/tests/test_release_public_web.py`，包含实际隔离 Chromium 渲染，但不代表真实网站获取或语义质量验收已完成。

获取记录补齐：新自动 Snapshot 保存 `source-acquisition.v1`，包括实际请求/落地 URL、时间、文档响应状态与 hash、TLS/公网访问策略和提取正文 hash；Completion Manifest 同时绑定该记录 hash。复用保留原始获取时间与记录，不伪造重新获取。人工粘贴不能创建传输证明；旧快照记录为空，保持原有可消费正文，不追认官方身份。页面展示实际落地地址；域名匹配不是事实证明。正文达到200,000字符保存上限时保留 PARTIAL，不冒充完整页。迁移 `20261009_04` 只新增来源记录列；初始迁移的原 Snapshot 定义固定，避免随 ORM 漂移而重复加列。

正文状态：PENDING_FETCH、FETCHING、READY、PARTIAL、UNAVAILABLE、REJECTED_CONTENT。保留限制继续是处置方式，不表示正文已 READY。真实网络故障允许恢复；不可消费页面不进入事实支持关系。
