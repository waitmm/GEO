# Monitor 指标与优化机会

文档编号：PRD-MON。里程碑：M1。版本：2026-09-30。实现状态：未核查。

业务依赖：BRD、PRM、SAM。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

用户在项目首页看见品牌在哪些问题中被提及、列为选项、明确推荐和引用，并找到值得优先分析的问题。默认轻量分析，不对所有 Prompt 自动运行深度证据链。

## 页面和主要操作

项目首页：指标摘要、覆盖率、Prompt 列表、意图与平台筛选。
Prompt Monitor：样本明细、趋势、品牌与竞品观察、引用观察、“分析优化”入口。
机会卡：建议优化/值得观察/暂不优先，附触发原因、数据范围和限制，不显示伪精确机会总分。

## 正常流程

1. 采样完成后运行基础实体与行为观察。
2. 按每个指标的有效判定样本计算计数和比例，同时展示采集和分析覆盖。
3. 按 Prompt、版本、平台、时间窗口查询；明细可定位到原始答案。
4. 根据问题目标、业务重要性、竞争差距和覆盖程度生成机会建议。
5. 用户选择机会进入明确范围的 Optimize；不会自动重算整个项目。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| mention / option / recommendation | 布尔或 UNKNOWN | 已明确推荐计入 option 与 mention；引用域名单独出现不自动算文本提及 |
| owned_domain_citation / brand_citation | 分别判定 | 域名归属与引用内容涉及品牌是两个不同观察 |
| third_party_citation / competitor_observations | 按已知身份分类 | 普通平台、媒体不自动当作竞争品牌 |
| eligible_n / observed_n / selected_n | 每指标保存 | UNKNOWN 不计为零；n=0 显示暂无有效数据 |
| metric_version / brand_config_version | 必需 | 跨模块复用同一规则与输入 |
| opportunity_reason_codes[] | 必需 | 解释性规则，不使用未经校准的总分 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| MON-001 | Mention、Option、Recommendation 的基础定义共用同一语义投影。 | 推荐不是所有列举，候选不是任意提及；具体示例见契约文档。 |
| MON-002 | 分母按指标已完成的合法判断计算，旁边展示未覆盖数量。 | 不得用 3 条已算样本宣称固定 9 条全部完成。 |
| MON-003 | 项目级优先展示 Prompt Macro Average。 | 无有效分母的 Prompt 不按零处理；参与 Prompt 数和范围必须显示。 |
| MON-004 | 机会规则结合目标适用性，覆盖不足显示限制但保留用户主动优化入口。 | 概念类不因低推荐自动高机会；复杂准确性判断只消费已有深度结果。 |

## 状态和异常

指标状态：PENDING、AVAILABLE、PARTIAL、UNAVAILABLE；指标值为 0 与不可用不同。趋势须标出配置、模型或 Prompt 集变更。不同意图的主要目标按适用范围聚合，不把不适用指标强制纳入一个总分。

## 验收场景

| 用例 | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-MON-01 | MON-002 | 选定九条，三条完成推荐判断且一条推荐 | 展示指标 | 显示 1/3 与覆盖 3/9；不能显示 1/9 或全集完成。 |
| AC-MON-02 | MON-002 | 九条均完成且没有推荐 | 展示指标 | 显示 0/9，而非暂无数据。 |
| AC-MON-03 | MON-003 | 两个 Prompt 分别 1/2 和 9/10 | 项目聚合 | Macro 为 70%；若展示 Run 加权 83.3%须分开命名。 |
| AC-MON-04 | MON-004 | 用户点某机会 | 打开 Optimize | 项目、Prompt、版本和选定范围准确，不触发其他 Prompt 计算。 |
| AC-MON-05 | MON-001 | 三条答案分别为无关提及、有效候选和明确推荐 | 计算基础行为 | Mention/Option/Recommendation 按定义分开，明确推荐计入候选与提及。 |

各场景初始状态均为 NOT_RUN。验收结果填写到 [验收矩阵](17_验收矩阵.md)，不得因文档齐全就标为通过。
