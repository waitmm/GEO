# Optimize 自动编排与结果版本

文档编号：PRD-OPT。里程碑：M2。版本：2026-10-09。实现状态：正式 API/worker/页面已接线，隔离模拟链路通过；真实模型质量和完整产品验收未完成。

业务依赖：PRM、SRC、MON。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

用户点击分析优化后，系统自动完成答案分析、引用分析、事实判断、策略和执行稿交付。逻辑阶段可以由同一服务编排，不要求每阶段增加页面、模型调用或人工确认。

本文要求非空且有针对性的行动交付；合法输入不得因低引用匹配或无知识库返回成功空计划。无有效输入、执行故障与预算不足必须如实表达，不能伪造已完成。

## 页面和主要操作

Optimize 顶部展示分析范围、版本、当前阶段、覆盖及耗时。正文按“诊断摘要—行动方案—具体交付—依据与限制”组织。技术细节收在展开区。可查看旧版本、继续任务、重试失败阶段和修正输入。

## 正常流程

1. 冻结项目、品牌、Prompt、run_ids 和配置版本，创建任务。
2. 解析可选 Context；为空时继续。对答案和引用形成结构化结果。
3. 生成事实使用边界、机制假设与行动候选。
4. 解析资产和渠道，编译执行稿，运行自动 QA 与局部修复。
5. 发布新的完整结果版本；页面展示来源和具体交付。
6. 用户纠错后只重算受影响部分；原版本保留并标记替代关系。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| analysis_id / context_id / scope_hash | 必需 | 范围与身份不得靠隐式 latest 选择 |
| result_version / input_versions | 完成或中间结果必需 | 消费者显式接收对应版本 |
| stage_status / coverage | 系统生成 | 缓存命中、待计算、失败不同 |
| budget / usage / retry_policy | 任务记录 | 额度与超时可解释，禁止无限修复 |
| actions[] / deliverables[] | 成功完成时非空 | 绑定当前 Prompt 观察，不得仅通用模板 |
| limitations[] / recovery_action | 按实际情况 | 不能把内容限制误作任务技术失败 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| OPT-001 | 机器链默认自动完成，人工审核作为可选纠错。 | 不能因未点击人工确认让所有动作永久 VERIFY_FIRST。 |
| OPT-002 | 资格是局部用途控制；可用证据少时通过探索策略和替换动作继续。 | 成功结果至少有当前问题相关的具体交付。 |
| OPT-003 | 缓存复用键必须包含语义依赖版本；缺失缓存进入待计算。 | 不能把缓存没有结果认定计算失败或合法零事件。 |
| OPT-004 | 真实失败可恢复，重试不得重复创建已成功结果或额外外调。 | 失败或预算中断不冒充空计划成功；恢复后继续原范围。 |

## 状态和异常

任务实际状态：QUEUED、RUNNING、WAITING_AUTHORIZATION、BLOCKED、INTERRUPTED、COMPLETED、COMPLETED_WITH_LIMITATIONS、CANCELLED。
COMPLETED 表示约定范围完成且交付通过当前文本检查；COMPLETED_WITH_LIMITATIONS 显示未评估范围和现有交付，不能冒充全集结论。低来源支撑是结果限制，不自动使任务失败。BLOCKED 保留具体程序或准入问题；WAITING_AUTHORIZATION 不等于失败或零事件。

## 正式入口和恢复

实现：`automatic_delivery.py` 复用 `diagnosis.py`、`citation_contribution.py`、`qualification.py`、`strategy.py`、`execution.py`；正文和实际文本检查使用 `delivery_generation.py`。页面 `AutomaticOptimizePanel.tsx`，持久表 `single_prompt_optimization_tasks`，迁移 `20261009_02`。

1. Optimize 选择已有明确 Analysis，或从 Run 池创建范围。页面“自动优化交付”选择可选品牌资料、正文版本或正文获取权限。
2. “开始自动优化”默认只消费合格缓存。缓存不足显示待授权，不自动扣费。API 为 `POST /api/v2/single-prompt/analyses/{analysis_id}/optimization-tasks`。
3. 对准确任务一次授权请求数、token、金额硬上限和核实计费依据；后续各计算阶段由同一 worker 连续交接，不逐层要求 Review。价格记录为操作者核实估算，不冒充账单实扣。
4. 页面稳定轮询真实阶段，已存在稿件可直接读取、复制；发布信息不阻止交付。停止只阻止后续请求，已外发请求仍记录用量。
5. 中断不自动重试。可核实的已完成对象/缓存继续复用；未结算请求或已失败的相同付费载荷不能通过恢复按钮重复收费。
6. 补录后显式选择新的正文 Completion ID/hash 创建新输入任务；旧任务和稿件继续使用原版本。不按 latest 换来源，不继承旧付费额度。
7. Monitor 的每日计划可一次授权有限的“每N批自动优化”，复用上述同一任务链；详细启停、范围和累计预算见[采样与样本池](03_采样与样本池.md)。未开启时只更新监测，不默认重做稿件。

在网络请求前被授权/预算拦截的 Answer 记为 PENDING_EXTERNAL_AUTHORIZATION，external calls=0；真实响应不合法仍是失败。请求已经发出但用量未核实，不能通过恢复按钮重新收费。

任务创建冻结原回答、品牌配置、Truth、Context版本、Provider/Model和计算契约。API、worker及调用前分别检查。来源范围不完整时可形成显式 PARTIAL 清单，但不能把缺失当作不支持；严格完整证据入口仍保留原 Gate。

## 验收场景

| 用例 | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-OPT-01 | OPT-001、OPT-002 | 品牌及有效答案存在，Context 为空 | 执行完整分析 | 生成诊断、具体动作和交付，不出现配置知识库 Gate。 |
| AC-OPT-02 | OPT-002 | 答案有效而引用匹配低 | 执行分析 | 产出探索策略和具体内容，说明依据与验证条件。 |
| AC-OPT-03 | OPT-004 | 同范围任务已运行 | 再次点击开始或刷新 | 复用现有任务或幂等返回，不重复外调。 |
| AC-OPT-04 | OPT-003、OPT-004 | 中间阶段完成后服务重启 | 继续任务并生成新结果 | 已完成部分可复用，身份、范围和历史版本不串用。 |
| AC-OPT-05 | OPT-003 | 有效输入尚无分析缓存 | 启动分析 | 进入待计算后正常处理，不能直接显示失败或零事件。 |

各场景初始状态均为 NOT_RUN。验收结果填写到 [验收矩阵](17_验收矩阵.md)，不得因文档齐全就标为通过。
