# Answer Intelligence 答案分析

文档编号：PRD-ANS。里程碑：M2。版本：2026-09-30。实现状态：未核查。

业务依赖：OPT。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

从有效答案提取用户需求、事实、步骤、规则条件、市场标准、品牌能力和决策理由，为策略提供可定位的输入。未提及目标品牌、无选择事件的回答仍需形成可分析结果。

## 页面和主要操作

答案分析详情显示原文及高亮片段、涉及实体、主要类型、语义侧面、选择行为、理由归属与限制。默认展示与当前目标有关的摘要，提供可选纠错。

2026-10-09 实现补充：稿件交付中的“查看分析依据”直接展示冻结完整回答和本方案选用的来源段落；“定位完整回答”按准确 Run 和 Unicode 字符偏移校验后高亮，不按相似文本猜位置，不读取 latest。该入口不会创建审核或外部调用。完整实体/选择行为的可视化和真实模型质量验收仍单独记录。

## 正常流程

1. 解析答案结构并保留原文偏移。
2. 识别 AnswerUnit 的主类型及可并存的语义侧面。
3. 识别目标品牌和竞品的提及、候选、推荐行为及范围限定。
4. 绑定理由与其主体，提取答案体现的任务要求和选择标准。
5. 将通用单位、品牌相关单位和合法零事件结果传给下游。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| answer_unit_id / run_id / text_span | 必需 | 可返回原始答案 |
| primary_type | 枚举 | PROCEDURE / RULE_CONDITION / FACT / MARKET_CRITERION / BRAND_CAPABILITY / DECISION_REASON |
| semantic_facets[] | 可为空 | 允许复合语义，不强迫一句话只承载一种意义 |
| entity_bindings[] / selection_events[] | 按观察生成 | 记录主体、行为及限制 |
| reason_bindings[] | 存在理由时生成 | 避免把竞品理由分配给目标品牌 |
| needs[] / uncertainties[] | 结构化输出 | 区分观察事实与模型解释 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| ANS-001 | 答案原文是观察对象，不自动等于真实产品事实。 | 答案声称具备功能需由 Truth 独立判断。 |
| ANS-002 | 选择行为按语义分类，不能只靠好用、推荐等关键词。 | 比较、否定、引用他人观点须保留语境。 |
| ANS-003 | 理由可被多个明确主体共享，但不得无依据广播。 | 保留各 Run 的真实观察归属。 |
| ANS-004 | 无品牌无决策事件也是合法分析结果。 | 仍提取任务需求和内容结构供策略消费，不重试到出现品牌为止。 |

## 状态和异常

单位处理状态与语义结果分开：PENDING、COMPLETED、FAILED；零事件为 COMPLETED 且 events=[]。语义不确定记录 UNKNOWN 或局部限制，不等于任务报错。

## 验收场景

| 用例 | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-ANS-01 | ANS-004 | 答案只有步骤，没有品牌选择 | 分析 | 返回步骤和需求、零选择事件，继续进入策略。 |
| AC-ANS-02 | ANS-002 | 答案明确不建议使用品牌 A | 分类 | 不能计为正向推荐。 |
| AC-ANS-03 | ANS-003 | 答案为竞品 B 给出某优势 | 绑定理由 | 不得计为目标品牌优势。 |
| AC-ANS-04 | ANS-001 | 用户打开一条策略依据 | 跳转答案单位 | 正确定位当前 Run 原文及上下文。 |
| AC-ANS-05 | ANS-001 | 答案声称品牌有某项能力，尚无证明 | 输出答案分析 | 记录这是答案中的声称，并交给 Truth 判断，不直接变为产品事实。 |

各场景初始状态均为 NOT_RUN。验收结果填写到 [验收矩阵](17_验收矩阵.md)，不得因文档齐全就标为通过。
