# Product Truth 与可选上下文

文档编号：PRD-TRU。里程碑：M2。版本：2026-09-30。实现状态：未核查。

业务依赖：BRD、ANS、SRC。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

独立判断目标品牌的原子事实，并向生成器提供可用表述、条件及限制。1.0 保留 EMPTY/BASIC ContextProvider；完整知识库后置。用户可补充事实但无需手工维护百科或逐项审批。

2026-10-09 轻量入口：粘贴资料、标题、出处，乐观版本校验后创建不可变版本；正文按段解析。执行稿明确选择版本，以当前问题确定性选取最多 5 段/6000 字，保留原文和出处，进入冻结输入及内部执行说明。未选择时返回 EMPTY，不隐式读取最新资料。该接线不等于完成自动事实核实，也不将用户文字放进公开能力声明。资料向自动 Optimize 更早阶段的接线仍待验收。

此前人工事实接线：`execution._machine_public_truths` 从精确 Answer/Truth 快照适配当前方向中已有公开资格的事实；`delivery_generation.generation_input` 复核快照 hash、出处、状态和限定，再给生成/QA 提供独立目标事实。空资料路径保持可用，不自动创建 Product Truth。缺出处、错 hash、竞品外推和条件丢失的隔离测试已执行。**人工事实可消费本身不是 AC-TRU-01 的自动来源核实证明；后续增量及限制见下文。**

来源证明的前置修复已接入 Snapshot：实际落地 URL 与传输/正文记录不可变绑定，重定向不能继续冒用原域名证明官方身份；历史无记录与人工补录均不自动升级。这仍只是获取来源证明，不是原子能力的语义支持、时效或冲突判断，不能据此把 AC-TRU-01 标为通过。

2026-10-10 实施增量（T13，IMPLEMENTATION_CHANGE）：自动稿件从本任务冻结的完整官方来源提取原子陈述，复用 V2 SourceClaim 与原文准入，再核对主体、完整支持、原子性、条件、获取时有效性、已给资料内冲突、发布主体身份及问题相关性。通过项以 `OFFICIAL_SOURCE_ATTESTED` 进入本稿；必须注明官方出处与资料获取时间，不升级为独立产品实测或无时间限制的当前事实，不自动写入全局 Product Truth。无资料、无通过项、历史缺获取记录或资料超过输入边界时继续交付其他有据表述/查证建议，限制随本稿保存。

费用仍由原任务统一授权、预占和审计，不新增预算平台：合格官方 Snapshot 数为 N 时，最多 N 次 SourceClaim 加 1 次集中核实，另有原正文生成与文本 QA 各 1 次；空候选不调用集中核实。资料累计最多 32000 字、最多 80 条候选陈述；越界明确未评估，不挑选方便通过的子集、不自动补调。契约变更产生新任务身份，旧授权不能静默升级。正文修改只复用该不可变核实记录并执行文本复检，不重复提取或核实。

当前证据：事实/安全/harness 专项80项通过（含28项事实测试）；来源、支持、条件、冲突、空资料、旧版回放和篡改均有独立断言。浏览器161951Z通过官方事实实际进入正文、页面读取、一次编辑 QA、旧稿保留；模型输出全部为隔离模拟。完整同源 harness 正在复检；真实模型质量未验证，不标 T13 DONE，也不将工程模拟记作真实品牌事实。

## 页面和主要操作

品牌事实面板展示原子 claim、证据片段、来源类型、适用条件、时效、冲突和用途资格。支持补充出处、纠正事实和查看影响范围。上下文缺失提示不遮挡分析入口。

## 正常流程

1. 从目标相关需求和答案提取需要核对的原子事实，复合表述拆开。
2. 使用当前有效官方资料、已获取公开资料和用户提供信息建立证据。
3. 判断支持、否定、未知与冲突，不把竞品能力当作目标品牌能力。
4. 按用途投影诊断、策略方向、执行草稿及公开表述资格。
5. 向下游提供可用事实及替代表达；无资料时仍允许不依赖未知事实的行动。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| claim_id / subject / predicate / value | 必需 | 带产品版本、场景或套餐等必要条件 |
| truth_status | 枚举 | SUPPORTED / NOT_SUPPORTED / UNKNOWN / CONFLICTED |
| provenance | 来源类型 | OFFICIAL_SOURCE_ATTESTED / FIRST_PARTY_ASSERTED / THIRD_PARTY_SOURCE_ATTESTED / OPERATIONALLY_VERIFIED / MACHINE_INFERRED |
| evidence_refs[] / valid_as_of | 有证据时必需 | 来源片段与核对时间 |
| eligibility_by_use | 系统规则投影 | 不同用途分别计算；不能只设总开关 |
| context_manifest / limitations | Provider 输出 | 空上下文也必须是合法返回 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| TRU-001 | 机器提取与来源证明分开。 | MACHINE_INFERRED 不能自动升级成公开确定事实。 |
| TRU-002 | 官方出处也要检查具体支持、条件、时效和冲突。 | 不是来源域名正确就全段可用。 |
| TRU-003 | 自动核实充分且无未解决冲突的事实可直接参与公开草稿。 | 不能给所有机器事实一律 VERIFY_FIRST 并要求人工确认。 |
| TRU-004 | 未知或冲突限制具体 claim；下游继续选择其他事实或表达方式。 | 策略探索标签不能使未知产品能力变成已确认事实。 |

## 状态和异常

Truth 与用途资格是两个维度。资格沿用 CONSUMABLE、VERIFY_FIRST、NOT_CONSUMABLE 等用途表达；限制需解释具体原因。用户补充视为新证据/纠错，并形成新投影，不以用户点击替代所有证据判断。

## 验收场景

| 用例 | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-TRU-01 | TRU-002、TRU-003 | 当前官方资料明确支持原子能力且条件一致 | 投影资格 | 可进入相应公开稿，不要求必经人工确认。 |
| AC-TRU-02 | TRU-002 | 资料只支持复合句中的一部分 | 拆分并生成 | 只使用已支持部分，其他部分另行处理。 |
| AC-TRU-03 | TRU-004 | 竞品具有能力但目标品牌未知 | 核对 Truth | 目标保持 UNKNOWN，不能从竞品外推。 |

| AC-TRU-05 | TRU-001 | 模型仅从竞品类比推断目标能力 | 投影公开使用资格 | 保持待核实，不能把推断变成有来源证明的公开事实。 |
