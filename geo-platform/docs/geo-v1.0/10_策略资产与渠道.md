# 策略编译及资产渠道解析

文档编号：PRD-STR。里程碑：M2。版本：2026-10-10。实现状态：已有自动资格/方向及资产渠道编译、实际稿件接线与隔离浏览器验证；通用业务价值和真实集成仍待验收。

当前复用 `single_prompt_v2/qualification.py`、`strategy.py`、`execution.py`。没有品牌事实或资料不是全局阻断，资产未知保留条件式更新/新建，渠道建议不得证明AI一定采纳。具体建议和稿件可从正式Optimize页面查看；当前模拟传输页面通过不等同于所有策略/渠道选择合理，AC-STR系列业务验收状态不因此升级。v7保留回归，不是当前唯一交付入口。

业务依赖：ANS、CIT、TRU。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

把当前 Prompt 的需求、品牌表现、引用支撑与事实边界编译成可执行行动。优先利用已有资产与真实问题，确保有效输入有非空具体交付路径。低证据时产生有依据的探索性行动，不生成与当前问题无关的通用文章凑数。

## 页面和主要操作

策略卡展示问题依据、目标、主要行动、资产、渠道、具体交付入口、策略性质与验证方式。默认突出最值得先执行的动作；其他候选和排除理由可展开。数量由有效动作决定，不预设固定三篇或固定渠道。

## 正常流程

1. 汇总观察事实和不确定性，形成可行动的瓶颈假设；未知不直接等于缺口。
2. 依据结构化输入与可解释规则提出候选；LLM负责解释组织，不凭空声明原因。
3. 确定资产角色，再检查已知官网/现有相关资料，选择更新、新建或条件方案。
4. 根据适配、可控性、可观察性和引用观察选择渠道，并明确选择理由。
5. 对缺少事实的候选替换表述或行动；输出具体执行要求和探索验证条件。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| action_id / input_result_version / basis_refs[] | 必需 | 每项行动关联当前问题的具体观察 |
| mechanism_gap / hypothesis | 按证据填写 | CONTENT / DISCOVERY / SELECTION / ABSORPTION / ASSOCIATION / DECISION；支持并存与 UNKNOWN |
| strategy_intent | 枚举 | EXPLOIT / EXPLORE / OBSERVE；OBSERVE 可作配套任务 |
| asset_role / asset_operation / target_asset | 必需 | 角色与 CREATE_NEW/UPDATE_EXISTING/CONDITIONAL 分开 |
| primary_channel / channel_roles / rationale | 必需 | 无可控权限时提供渠道适配内容和执行前提 |
| validation_contract | 必需 | 假设、干预、观察信号、窗口、采样安排及判断限制 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| STR-001 | 成功计划至少包含一项针对当前 Prompt 的具体发布或上线交付。 | 不能只剩补事实/继续观察；未知事实通过调整路径处理。 |
| STR-002 | 机制标签是有依据的诊断或假设，不是对引擎内部机制的已知事实。 | 缺少引用不能直接证明未检索或未学习。 |
| STR-003 | 未知资产状态不能自动 CREATE_NEW，也不能阻断内容方案。 | 给出同一具体内容交付的更新/新建条件，并主动检查已知资产。 |
| STR-004 | 官网不是永久 PRIMARY，引用多也不是渠道必选理由。 | 渠道选择须解释与本次资产的关系。 |
| STR-005 | 探索动作使用已核实事实并明确验证条件。 | 策略可能有效与产品事实可能为真是不同问题。 |

## 状态和异常

单项动作可为 READY、LIMITED、NEEDS_REWRITE、SUPERSEDED。Plan 技术失败与动作资格不足分开：局部不合格进入自动改写/换动作；整个成功结果不能仅标 BLOCKED。新方案绑定新结果版本。

## 验收场景

| 用例 | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-STR-01 | STR-001、STR-002、STR-005 | 引用不充分支持答案但需求清晰 | 编译策略 | 仍输出基于需求的具体动作、适配渠道和验证安排。 |
| AC-STR-02 | STR-003 | 未登记场景页 | 编译资产动作 | 先检查已知资产；交付具体方案及条件，不盲目新增重复页。 |
| AC-STR-03 | STR-004 | 引用平台多但不适合可执行交付 | 选择渠道 | 说明取舍，不按引用次数硬选主渠道。 |
| AC-STR-04 | STR-001、STR-005 | 一个动作依赖未知品牌能力 | 生成最终计划 | 自动调整或替换动作，仍有有用的具体交付。 |

各场景初始状态均为 NOT_RUN。验收结果填写到 [验收矩阵](17_验收矩阵.md)，不得因文档齐全就标为通过。
