# Execution Draft 与自动质量检查

文档编号：PRD-EXE。里程碑：M2。版本：2026-10-10。实现状态：冻结输入驱动的生成/文本QA/局部修复、编辑复检及导出已实现并有隔离验证；真实模型质量与完整产品验收未完成。

当前实现边界：现有 V2 自动任务冻结品牌、问题、回答、来源、策略、相关BASIC资料及显式补充来源版本；有限预算下由模型生成实际段落，再以独立文本QA与确定性检查验证主体、数字、条件、来源绑定。不能修复的事实段删除或退回已有归因内容，保存真实问题/修改前后/复检，不返回静态修复列表。公开品牌陈述只消费本任务合格事实，BASIC文本不是事实凭证。正文可复制、编辑为新版本及精确导出Markdown；内部QA/审计不混入正文。六路径组合041247Z通过工程验证，真实模型写作价值、语义核实质量及更多资产形式仍未完成验收。v6/v7为[历史回归切片](single-run-delivery-acceptance-2026-09-30.md#9-2026-10-08-稿件交付器修补)，不再是当前生成器能力的全部定义。

业务依赖：STR、TRU。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

将行动编译成可直接修改、发布或上线的交付。内容草稿包含具体文字；页面更新提供实际替换/新增内容；技术调整提供针对已观察问题的明确修改说明。不得用只有标题的大纲或“建议完善官网”等通用模板作为最终成功交付。

## 页面和主要操作

2026-10-12 资产核查补充（IMPLEMENTATION_CHANGE，SC-ASSET-001）：复用现有方案修订保存明确的用户核查快照，不建立第二套执行主链。更新已有页面需提供 URL、标题、当前版本、归属/权限依据并确认可编辑、内容适配；新建需说明盘点范围并确认已完整核查且没有适配现有资产。仅勾选账号可操作不能代替资产核查。资产类型或承载位置改变后原核查不适用。记录标明 USER_REPORTED、操作者、时间、原版本和快照 hash，不冒充系统验证，不把 SourceSnapshot 自动纳管。信息缺失只影响发布确认；正文、QA、分析输入及原任务保持不变，零新增模型调用。原结果永久保留；完整资产发现、自动权限验证不在本增量已实现范围。

2026-10-12 精确版本补充（IMPLEMENTATION_CHANGE）：方案详情按链接中的 proposal/result 成对读取，显式不存在、空版本或其他方案版本必须拒绝，不能退回当前版本。历史正文及其QA保持原样，不能据此新编辑或确认；已有精确确认仍可登记对应历史发布报告。所有修改、确认、发布写入必须先核对项目、Prompt、策略与方案归属，再提交。隔离回归及正式页面操作另列证据，不修改历史业务记录。

交付页分为发布内容、执行说明、证据与限制三个区域。发布内容可复制/导出；内部假设、缺失资料清单和技术 ID 不混入面向读者的正文。展示当前版本与自动检查结果，用户可编辑并重新检查。

2026-10-09 实现补充（等待同版浏览器总验收）：生成稿可编辑章节标题、正文段落并增删建议段落/章节。编辑起点为已修复正文，不恢复被删除的错误文本。保存将精确原稿版本、冻结交付输入和修改稿绑定到现有 V2 队列中的独立复检任务；旧任务、原稿与 QA 不覆盖。未变化提交复用原任务。新任务默认 CACHE_ONLY，缓存不足时明确等待一次 QA 请求授权，不能继承旧任务余额；不重跑 Answer、Citation 或生成器，不抓取新资料。完整复检及局部修复后形成新的 Execution ResultVersion；失败或无可用正文不能继承 READY。当前主标题仍取冻结问题，不提供任意标题改写；段落不得添加不存在的事实依据。以上不表示自动官方事实核实或自由成稿通用质量已完成。

## 正常流程

2026-10-10 显式重新生成补充（IMPLEMENTATION_CHANGE，待浏览器复检）：从准确已交付版本发起“重新生成正文”，使用现有V2队列中的`delivery_text_regeneration.v1`任务。冻结分析、资料、策略及已合格事实凭证不变；不重跑Answer/Citation/SourceClaim或抓取。默认仅缓存，独立授权最多生成和QA各一次；同一基稿重复提交幂等，生成身份进入缓存键。兼容的相同文本QA可复用，不伪装为新调用。新版本保留原稿与所有历史QA，无实际修复时为空；失败不继承READY。它不代表资料已更新，换资料必须明确选择新版本建立任务。

1. 接收动作、目标渠道、资产状态和事实使用边界。
2. 生成适合动作的具体交付：页面修改、场景说明、FAQ、教程、对比或其他已支持形式。
3. 抽取实际稿件包含的 claim，检查来源、条件、主体、数字、承诺与冲突。
4. 检查交付是否解决当前问题，是否有信息增量，以及渠道格式是否可用。
5. 局部失败自动改写或换用不依赖缺失事实的方案；在已配置预算内重新检查。
6. 通过后投影版本资格并允许复制导出；编辑产生新版本并检查差异。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| draft_id / draft_version / content_hash | 必需 | 发布资格绑定精确版本 |
| action_id / target_asset / channel | 必需 | 可追溯策略与目标 |
| deliverable_type / content | 必需 | 新页面全文、片段替换、FAQ、明确技术改动等 |

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| EXE-001 | 发布内容必须针对当前 Prompt 与品牌任务。 | 不能为了满足非空输出而交付任意泛科普。 |
| EXE-002 | 不以固定字数、块数、FAQ Schema 数量作为通用通过条件。 | 以问题回答、信息增量、事实和渠道适配验收。 |
| EXE-003 | 生成前事实约束与生成后实际文本检查都必须存在。 | 来源只支持访问统计时不能扩写成成功加粉统计。 |
| EXE-004 | 待补截图/数据不得伪造，待补项不能成为可发布正文的占位符。 | 已有材料不足时调整稿件，材料清单置于执行说明。 |
| EXE-005 | 单项检查失败自动修复，预算耗尽显示明确技术待恢复状态。 | 不能返回“成功”但只给错误列表或空草稿；不得无限循环外调。 |

## 状态和异常

DRAFTING → CHECKING → REPAIRING → READY；异常为 NEEDS_RECOVERY，旧版本为 SUPERSEDED。编辑后的版本进入待检查，原版本的资格不自动转移。事实限制与效果不确定性分别展示，不要求用户逐条点击审核才能复制已合格内容。
