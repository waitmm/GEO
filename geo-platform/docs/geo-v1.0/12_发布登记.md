# Publication 发布登记与执行一致性

2026-10-09 范围决定：本模块及 PUB-* 从本版必需交付移出，T20/AC-PUB-* 为 OUT_OF_SCOPE，不是 PASS。既有发布记录和历史功能保留；不得控制采样、Optimize、Monitor、Validate 或稿件查看。下文保留可选功能定义，不再构成主链依赖。

文档编号：PRD-PUB。里程碑：M3。版本：2026-09-30。实现状态：未核查。

业务依赖：EXE。共用规则见 [数据与状态契约](16_共用契约与状态.md)。

## 目标与范围

用户在外部完成发布或页面更新后，系统记录实际执行内容，与策略和草稿关联，为复测提供基线。自动发布、CMS 广泛集成不列入本版新增范围。

## 页面和主要操作

执行稿页提供“登记已发布”；默认只要求发布 URL 和时间（允许确认系统建议时间）。自动展示关联策略、原草稿、抓取内容及主要差异。抓取不到时提供可选正文/截图补充和限制说明。

## 正常流程

1. 从具体执行稿进入登记，自动携带动作与版本。
2. 提交 URL 和发布时间，校验归属项目与地址格式。
3. 自动抓取并保存实际发布快照，提取标题、平台与可访问状态。
4. 比较原草稿与实际内容：核心事实、页面目标、主要区块和执行差异。
5. 记录执行一致性与限制，创建待复测记录或进入复测配置。

## 输入输出与业务字段

| 字段/对象 | 要求 | 语义 |
|---|---|---|
| publication_id / action_id / draft_version | 必需 | 不能仅关联 Prompt 而丢失具体干预 |
| url / platform / published_at | 登记必需 | 实际时间不明时保存声明时间与精度，不伪造精确时间 |
| registered_at / captured_at | 系统生成 | 发布时间与抓取时间分开 |
| published_snapshot_id / content_hash | 可抓取时必需 | 实际内容，不能用原稿冒充 |
| fidelity / diff_summary / limitations | 系统生成 | 一致、部分一致、明显偏离、不可判断 |
| change_reason | 可选 | 重大差异可询问，不要求所有用户必填长表单 |

以上是业务信息要求，真实表和接口复用映射由 M0 完成，不强制按字段新建一套模型。

## 需求与规则

| 需求编号 | 行为要求 | 可观察标准 |
|---|---|---|
| PUB-001 | 原策略、原稿、来源由系统继承。 | 不让用户重新手填系统已有资料。 |
| PUB-002 | 实际发布稿独立保存并自动比较。 | 原稿通过 QA 不等于修改后的发布稿自动通过。 |
| PUB-003 | 抓取失败可以登记并继续安排复测，但标记执行一致性未知。 | 不能把缺少发布核查直接解释为策略无效。 |
| PUB-004 | 多 URL、多次更新分别记录或组成显式干预组。 | 不能覆盖早期干预时间，复测必须绑定选定干预版本。 |

## 状态和异常

REGISTERED → VERIFYING → VERIFIED / LIMITED / UNREACHABLE。上述状态记录发布可验证性，不是优化 Plan 的完成状态。用户可补充材料形成新核查结果。页面后续改变保留新快照，不覆盖当时发布版本。

## 验收场景

| 用例 | 需求 | Given | When | Then |
|---|---|---|---|---|
| AC-PUB-01 | PUB-001 | 已有合格执行稿 | 只提交 URL 与发布时间 | 策略与来源自动关联，不要求重复填写。 |
| AC-PUB-02 | PUB-002 | 实际页面改掉了核心事实 | 自动比较 | 明确差异并对新表述做必要检查，保留实际快照。 |
| AC-PUB-03 | PUB-003 | 发布 URL 有效但抓取受限 | 登记 | 保存限制并允许复测，不能伪称页面已核验。 |
| AC-PUB-04 | PUB-004 | 同干预同页面相同版本已保存 | 重试提交 | 不重复创建同一次发布；实际更新允许新版本。 |

各场景初始状态均为 NOT_RUN。验收结果填写到 [验收矩阵](17_验收矩阵.md)，不得因文档齐全就标为通过。
