# 共用对象与状态契约

这些是业务与模块交接约束，不是已存在的表结构、HTTP 路由或 OpenAPI。M0 必须映射到真实仓库；优先复用已有模型和接口，避免按文档名逐一新建服务。字段可沿用现有命名，但语义和身份关系必须保持。

## 身份与版本

| 对象 | 必要身份/内容 | 消费约束 |
|---|---|---|
| Project/Brand | 项目、品牌、别名、域名、配置版本 | 一切查询写入受项目归属约束 |
| Prompt | 问题文本、版本、目标、意图 | 修改不覆盖旧样本的问题 |
| Sampling Run | 逻辑样本、尝试、采样入口、原答案、时间 | 重试不是新独立样本 |
| Analysis Scope | 明确 run_ids、问题/品牌版本、scope_hash | 提交后不可自动纳入新增 Run |
| Source Snapshot | 来源角色、正文、hash、获取时间 | 被引用过的快照不原地覆盖 |
| Answer/Citation/Truth Result | 输入版本、结果版本、覆盖、限制 | 后续显式交接，不查询任意 latest |
| Strategy/Execution | 动作、具体稿件、证据及 QA、版本 | 资格绑定实际内容版本 |
| Publication | 动作、原稿、真实发布快照、时间、差异 | 不用原稿代替发布稿 |
| Retest/Experiment | 基线、发布、复测范围、配置差异、结果 | 不静默替换基线或删除负向轮次 |

## 必须分离的状态维度

采集状态描述是否得到合法答案；分析状态描述是否处理完成；语义值描述品牌出现与否；覆盖描述固定范围完成了多少。不能用一个“失败/成功”字段混装所有含义。

例如：collection=SUCCEEDED、analysis=PENDING、mention=UNKNOWN 是合法状态；collection=SUCCEEDED、analysis=COMPLETED、mention=false 也是合法状态，后者才是已观察未提及。正文获取失败不代表原答案无引用。分析缓存缺失进入 PENDING_COMPUTE，不等于 FAILED。

任务等待外部条件必须有原因，PARTIAL 必须有覆盖和未完成对象。语义零事件为合法完成。整体成功要求范围处理与预期交付均完成；部分结果可展示，但不能误标全集结论。

## 指标口径

本包提出以下操作性口径，M0 对照现有已验证实现；若不同，先明确语义差异并形成一个统一版本，不维持两套悄然不同的计算。

- Mention：目标实体在答案语义中被明确指代，包含经过消歧的名称/别名；仅引用域名出现不自动算正文提及。
- Option：品牌被纳入能够满足任务的候选方案。纯举例、批评性列举、无关提及不自动算候选。
- Recommendation：存在明确正向选择或优先推荐，保留场景条件。否定、不适用说明不计为正向推荐。
- 本版聚合采用 Recommendation ⊆ Option ⊆ Mention。底层保留原始行为类型，不能为了套关系改写原文观察。
- Citation 指标分别描述官方域名出现、第三方来源出现和品牌相关引用；来源归属未知单列。引用支持关系属于深度分析，不混入基础“出现率”。
- Rate = 已完成有效判断中的正向逻辑 Run 数 / 该指标已完成有效判断的逻辑 Run 数。一次 Run 同一品牌重复出现只计一次。n=0 为 N/A，不是 0%。
- 每个比例同时显示 selected_n、collected_valid_n、metric_eligible_n。缺失不是随机的可能影响代表性，覆盖不足时不声称完整范围结论。
- Prompt Macro 为相同切片下可用 Prompt 比例的算术平均；展示参与数及未覆盖 Prompt。Run Weighted 另列，不能混名。
- 前后差默认给出计数及百分点；基线为零不计算普通相对增长率。
- 前后 Prompt 集变化显示差异，可提供共同问题集趋势。不同目标的主指标按适用范围计算。

## 逻辑交接操作

| 操作 | 输入 | 输出 | 关键校验 |
|---|---|---|---|
| StartSampling | 项目、Prompt版本、入口、次数、幂等键 | job_id、目标样本数、状态 | 可用采样配置、调用边界 |
| GetMonitoring | 项目、范围或时间切片、指标版本 | 计数、分母、覆盖、限制 | 查询无业务写入 |
| StartOptimize | 明确范围、品牌/Prompt版本、预算 | analysis_id、冻结输入、任务状态 | 无有效答案时解释失败；低匹配不拒绝 |
| ResolveContext | 项目、品牌、问题、答案单位、当前任务 | relevant_context、sources、limitations、manifest | EMPTY 为合法结果，不触发用户必填知识库 |
| CompilePlan | 分析结果版本、Truth、资产线索 | actions、draft specs、validation contracts | 非空、针对性、引用角色正确 |
| CheckDraft | 精确稿件版本、可用事实与来源 | 文本问题、定位、资格、修复要求 | 新增 claim 与范围扩大检查 |
| RegisterPublication | 动作/原稿版本、URL、时间 | 发布记录、核查任务 | 幂等、项目归属、实际稿快照 |
| StartRetest | 发布/基线、配置、窗口、预算 | 复测任务、冻结方案 | 可比性差异显式化 |
| ApplyCorrection | 对象与原版本、新信息和来源 | 影响范围、新任务/投影版本 | 并发冲突，不全库重算 |

所有耗时操作返回任务身份，轮询/事件机制沿用现有可用方案。写操作具备幂等和归属校验；真实接口路径由 implementation-map 记录，不在未读代码时虚构。

## 事实与策略资格

SUPPORTED 描述证据对原子事实的支持；public_claim=CONSUMABLE 描述该事实在当前条件下可用于公开稿。来源可信、事实匹配、时效和冲突都参与用途投影，不以一个置信度阈值代替。

EXPLORE 描述行动效果假设。它不能把 UNKNOWN 产品事实升级为确定宣传。公开稿中不出现内部待核实占位；系统在事实边界内调整内容或替换行动。

预检查 → 内容生成 → 实际文本检查 → 局部修复 → 资格投影是业务顺序，不要求新增五个独立服务。是否额外调用模型按实际风险与现有能力选择，不为每条确定性检查强制增加一次 LLM。

## 并发和恢复

新任务冻结输入；同一身份重复提交幂等返回。多个任务完成顺序不能决定谁覆盖谁：结果按其自身身份版本保存，当前视图只消费用户选定上下文。

纠错、新来源和编辑内容触发受影响部分更新。历史原始观察保留；错误派生计划和计算缓存可明确标废或安全清理重算，不能把它们作为长期兼容义务。真实用户已发布的资产和实验记录不随派生清理删除。
