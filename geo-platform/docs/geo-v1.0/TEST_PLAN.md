# 1.0 测试执行说明

版本：2026-10-10。依据 SC-DELIVERY-001；不是已完成验收声明。本文件说明现有 harness 的执行方法，不建立第二套任务或状态。状态以 [验收 JSON](acceptance_cases.json) 为准，需求与实现见 [追踪表](21_需求任务验收追踪.md) 和 [实现映射](implementation-map.md)。

## 环境与隔离

- 已测环境：macOS、Python3.14.3、Node24.14.0、应用 SQLite3.51.3、WAL、外键开启。以运行报告记录的实际值为准。
- 在 `backend` 使用 `.venv/bin/python`，不解析到系统 Python；前端命令需要安装后的 Node/npm PATH。
- pytest 使用临时数据库；浏览器脚本新建迁移库和临时 loopback 端口，通过正式 API/页面操作，结束后关闭本轮服务。不得清空正式库或借真实定时计划测试。
- `scripts.delivery_offline_guard` 禁止离线测试出网；浏览器只允许本轮本机地址。模型/抓取替身位于传输边界，业务状态、版本、数据库和页面不是统一伪造成功。
- 备份包括数据库及明确列出的 artifact 根目录；凭证和浏览器登录 profile 不自动打包。恢复目录必须新建，禁止覆盖正式库。

## 执行入口

从 `geo-platform/backend` 运行：

```bash
.venv/bin/python scripts/delivery_acceptance.py
```

顺序为适用后端套件、启动配置检查、客户端检查、release 构建、七条隔离浏览器路径：项目/计划、Monitor/Validate、无资料 Optimize、已有官方资料、BASIC 版本更新、补充公开资料、邀请登录与项目隔离。运行中不得修改源文件或另外构建同一 `dist`；报告检查前后源文件指纹。权限路径使用仅限隔离库的合成凭证，检查错误凭证、键盘登录、刷新会话、越权深链、退出与服务端撤权；不代表远程TLS部署通过。

报告保存于 `backend/artifacts/acceptance/<UTC批次>/report.json`，含原提交/工作树、命令、退出码、JUnit、用例具名断言匹配及缺口。浏览器目录另有截图、trace、完整 axe 结果和未自动判断项。失败报告保留；局部复检不能回写失败批次为 PASS。

- `--checks-only` 允许工程检查结束，不代表产品完成。
- `--coverage-only` 只检查映射，不能替代执行。
- `--skip-browser` 不能得到产品完成判定。
- 工程全绿但必需用例或任务未完成时，整体仍为 INCOMPLETE，默认命令返回非零。这不是通过率计算错误。
- 不相加专项与全套数字；参数化断言在同批 JUnit 中独立计数，跨批复检仍可能重叠。

## 三条最终线路

**A 首次使用到稿件：** 创建新项目/Prompt，取得已支持平台的真实新Run，明确选样并完成自动Optimize。核对具体问题、行动、渠道、正文、QA与导出；至少一个本版真实平台和模型路径通过。原v7仅用于回归。

**B 持续监测到比较：** 配置有限计划，执行后续真实采样；在没有发布记录的情况下比较。核对样本条件、分子分母、引用增加/持续/未再观察到及不可比限制。不要求上涨。

**C 资料与恢复：** 空资料交付后，保存/选择相关BASIC或补充来源新版本；旧任务输入不变。只重算受影响阶段，检查缓存、失败恢复、预算累计、服务重启和项目隔离。

真实集成必须另有明确平台/模型、项目/问题、次数/token/费用上限；有凭证不等于有本批授权。当前新增集成批次仍待明确授权，不得套用已结束的9-Run、P1或Critic预算。遇登录/验证码或预计超预算停止对应调用，其他工程继续。任何外部调用失败同样记入预算和结果。

## 判定与复检

每项PASS必须对应用户行为、持久状态和可复核预期；请求200、模型自评READY、构建成功均不足。来源真实、内容对应、公开用途资格及生成因果分别判断。不得由资料域名或“探索方向”标签豁免事实检查。

先复检直接影响范围，再对最终候选完整运行。同一失败若是fixture过时，说明原/新契约并保留有意义负例；若是实现缺陷，修实现而不放宽预期。只有全部必需缺口关闭才允许最终完成，真实发布/收录/引用上涨不作为前置。
