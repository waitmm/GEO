# GEO 1.0 使用手册

适用入口为 release 控制台，不是旧实验页面。当前版本的验收状态见[验收矩阵](17_验收矩阵.md)；本手册不构成全部功能已验收声明。

> **当前版本边界（2026-11-05）**：公司 M1.1 Windows 试用尚未部署；M1.2 多内容仅在
> `codex/m1-2-multicontent` 完成离线候选验收，不会自动出现在 M1.1。下文中旧单稿流程继续适用；
> 本页“M1.2 多内容候选”一节只用于研发候选验收，不能理解成真实双稿质量已经通过。

## M1.2 多内容候选

一次 AI 优化仍只有一个冻结的父结果，诊断、策略、Evidence、Prompt/Run 范围和 Product Truth
都绑定在该父结果上。用户可选择帮助文档（HELP_DOC）、常见问题（FAQ）或两者；选择两种时，
系统在同一个父结果下追加两份彼此独立的内容资产，不创建两个互不相关的 Optimize 结果。

- 帮助文档应解决“如何完成操作”，正文必须含可执行步骤；FAQ 应覆盖具体疑问与边界，不能只是帮助文档换标题。
- 每份资产分别显示生成状态、Evidence、QA、VERIFY_FIRST、复制、Markdown 导出和反馈。
- 父任务允许部分成功。一份资产失败时，已成功资产仍可查看和导出；失败资产不能伪装完成，也不能借用兄弟资产的 Evidence 或 QA。
- “重新生成这一份”只为该资产追加新版本，旧版本和另一份资产保持不变。返回历史版本时仍显示当时正文、Evidence 和 QA。
- `VERIFY_FIRST` 表示内容可作为编辑底稿，但列出的品牌能力或事实在使用前仍需核验；品牌关联目标不是 Product Truth。
- 历史单稿结果继续按原方式显示，不会在数据库升级时被改写成两份资产。

当前隔离验收使用脚本化结果，不产生外部模型费用。真实 HELP_DOC + FAQ 的内容价值、事实准确性和
差异化仍需独立模型授权和员工逐稿评价。

## 第一次使用

填写项目后可在表单底部核对保存预览：重复别名合并，域名留空显示未知，有域名也不代表系统已核实所有权。编辑会保留原地区和语言；保存失败不清空输入，修正错误后再提交。

1. 在顶部新建项目，填写项目名、品牌名及已知官网。官网可不填，不要用竞品域名代替；别名只填写确实指向本品牌的名称。
2. 打开“问题与采样配置”，输入一条完整问题，选择概念、工具选择或使用操作的实际意图；不确定时可暂未分类。多行内容仍是一条问题，不是多个搜索关键词。
3. 在 Monitor 从已有采样记录选择最近 7/14/30 天、自定义时间或明确 Run，核对回答数量和北京时间后冻结分析范围；采样与人工导入都在采样模块完成，Optimize 不再创建新样本。
4. 切换到该问题的 Optimize，选择刚冻结的范围并开始 AI 优化。新采样不会改变已冻结结果；已有分析可继续，不必重新采样。资料不足时保留限制并给出补充建议，不把未知信息补造成事实。
5. 尚无可用管理员额度时会显示“新 AI 优化暂不可用”。普通员工不填写请求数、Token、人民币或模型单价；这些限制由服务端管理员统一配置。刷新、恢复或失败不会自动增加额度。
6. 稿件完成后直接查看建议、渠道条件、完整正文和文本检查，使用“复制完整正文”或“导出 Markdown”。导出文件名包含结果版本，文件内容仅为该版已保存正文，不包含内部 QA 或待办；“正文下载已发起”不代表浏览器已允许或完成磁盘保存。不需要填写发布位置、确认发布或逐层审核才能获得内容。

点击稿件旁的“查看分析依据”可查看本版完整回答、选用来源的原始段落与品牌资料。在来源页点击“定位完整回答”返回准确 Run 的原文高亮。这里只展示本方案选用的依据，不代表所有引用都被实际使用，更不证明模型生成因果；补充品牌上下文和已核实事实分开展示。

“品牌资料”页同时列出本稿从官方来源自动核实的陈述、原文、出处、获取时间和未准入原因。自动核实仅消费本任务冻结且获取记录完整的来源，不会另行抓官网。此类公开表述必须保留出处、时间和适用条件，不代表独立实测或今天仍然有效；无需再逐条点击确认，也不会改变项目全局事实。无合格资料时仍可生成不依赖未知能力的内容。新增核实调用包含在该任务的显式总预算内，不另外自动加额度。

生成稿的“编辑正文并复检”可修改章节和段落。保存后先形成独立待检查任务，刷新仍能查看提交原文；旧稿在原任务中保留。修改稿不能继承旧检查结果。没有兼容缓存时，仅需为该任务授权一次文本 QA，不重跑回答和引用分析；修改后的合格正文及真实删除/改写记录另存新版本。未做任何修改则继续使用原稿。

“重新生成正文”则沿用该稿的冻结分析、来源和事实凭证，单独排队生成新正文并检查。不会重跑采样、回答或引用分析，也不会自动使用后来更新的资料。新任务没有旧任务额度，缓存不足时最多需授权生成和文本检查各一次；重复点击同一基稿不会重复建立任务。原稿仍可在旧任务查看，失败不会覆盖它。

从旧任务进入“方案详情与可选发布记录”，仍查看该份历史正文及当时检查，刷新不会改成新稿。历史版不允许新编辑或重新确认；已有确认的发布报告仍绑定原版。失效版本链接明确报错，可重试读取，不会自动展示另一稿件，也不会自动重新生成。

“当前资格暂不可用”只表示本次资格读取失败，已保存稿件仍可查看；使用“重试读取资格”恢复，不必重新生成正文。若保存的策略本身无法读取，则显示独立错误，可“重试读取结果”，不会把未知状态当成没有策略或改读其他版本。这两种读取重试都不调用模型。

当前方案详情可选择“更新已核实的页面”，填写已核查范围、页面URL、标题、版本以及归属和编辑权限依据，确认可编辑且适合承接稿件。选择新建时，必须确认已完整检查所填范围且没有适合更新的资产。保存形成独立版本并重新检查业务条件，不调用模型，不改正文和已有QA；信息不全仍可看稿件，只不能完成发布确认。这些记录由用户报告，不表示系统已验证账号权限。自动任务中的原交付仍链接原版本，修改后的业务版本以方案详情中的新版本链接查看。

API 正常不等于后台 worker 已运行。管理员须按[运行说明](15_运行与数据边界.md)启动 worker；否则任务会保持排队。不要反复点击开始创建新任务来代替修复运行条件。

页面顶部显示后台执行服务状态。未启动、心跳过期和暂时无法读取分别提示；API 可访问不代表自动任务正在执行。使用“核对后台执行服务”重新读取状态不会启动 worker 或产生外部调用。

误建且未使用的问题可从问题列表点击删除并确认；已有采样、计划或分析时只能停用，原始回答和历史结果不会被删除。

一次配置多个问题可点击“批量添加问题”，每项填写完整原文，最多20项。多行仍保留在同一个问题中。提交后逐项显示已创建、已存在或错误原因；修改错误项再提交，不会重复创建已成功项。新增问题默认暂未分类，可在列表分别编辑意图、问题组和优先级。此操作不启动采样。

## 持续监测

Monitor 可以查看整个项目或单个问题。按 Prompt 平均与按 Run 加权分开展示；未分析的候选/推荐指标显示不可计算，不能读成零。

问题行的“分析这 N 条回答”会把当前显示的可分析 Run 明确带入 Optimize。页面保留未进入分析的失败/空回答及原因。点击期间样本或配置发生变化时会要求刷新，不会悄悄替换输入；重复点击不会创建另一份相同分析。

展开“哪些样本未计入，为什么”可查看每条 Run 的具体原因。只出现一个可能是普通词的品牌别名，不直接算品牌提及；未消除主体歧义时保留未知。

每日计划选择时区、时间、单批数量和总尝试上限。新采样留在记录池，不改写旧分析。默认只采样；可另行启用每 N 批自动优化，明确最多任务数和每任务预算。暂停停止后续触发；已经运行的任务使用各自停止入口。

答案正文、平台生成的搜索词和引用是不同对象。来源被引用不证明它支持了所有回答内容，更不能证明模型内部生成因果。

## 品牌资料

“补充公开资料”可填写官网文档等公开 URL，明确勾选获取授权后提交。后台执行服务启动后才会获取；等待、失败、正文不完整分别显示，服务中断不会自动重试。再次提交是新的获取请求，不覆盖旧资料。

获取完成后，在自动优化的“新任务输入”中明确选择需要使用的公开资料版本（最多5份）。它们不是原答案引用，不增加引用数量。页面获取成功也不是事实核实通过；只有具体陈述通过本任务来源核实后，才能作为注明出处、时间与条件的稿件表述。任务详情和稿件依据显示已冻结资料，不随上方新任务选择框或项目配置改变。

“品牌资料”中粘贴正文并记录标题、出处，保存后产生新版本。在自动优化中明确选择需要消费的版本，或选择不使用补充资料。新资料不会静默修改旧结果。

资料读取失败时可点击刷新图标重试。已经排队或完成的任务继续使用创建时所选版本；采用新资料需要明确选择新版并创建新任务。未受影响的回答与引用判断会检查兼容缓存后复用，生成和文本检查仍受新任务的独立授权限制。稿件的“查看分析依据 → 品牌资料”显示本版实际采用的相关段落及版本号，不是当前最新资料全文。

用户资料用于理解需求，不自动变成已核实公开事实。系统不能把竞品能力写成目标品牌能力。公开稿中的事实、适用条件和来源要单独满足当前资格；模型 QA 也不是无限范围的真实性保证。

## 可选事实纠错

修改、审核和来源处置的操作人由当前登录身份自动记录，不能在表单中另填姓名。本机模式显示“本机操作者”；它只代表本机访问，并不证明某位自然人的身份。多人需要分别留痕时，由管理员配置独立邀请账户。此规则不改写以前保存的审核记录。

在已有自动分析任务点击“纠正品牌事实”，选择本任务实际使用的事实，填写单项内容、适用条件、人工判断、出处及依据。先预览受影响理由和方向，核对后勾选确认并保存。保存只增加纠错版本，不修改当前稿件，也不代替其他对象的审核。

需要采用纠错时，展开纠错历史点击“更新受影响内容”。这会建立独立任务，沿用原问题、回答和来源；只有受影响稿件可能需要新的生成/文本检查授权。原回答或引用没有兼容结果时会明确停止相关更新，不重新外调上游。不受影响的稿件仍在原任务；可从新任务返回。事实已被另一版本修改时需重新核对，不能覆盖。没有已冻结品牌事实时显示空态，现有内容仍可复制、导出。

## 变化比较

进入 Validate，明确选择基线与对照范围，可分别选择精确的 Answer 版本，再生成比较。没有发布记录也可以使用。

比较展示两侧分子、分母、覆盖和可比性，以及新增、持续、未再观察到的引用。查看两侧原回答核对变化。采样失败或引用不完整时，不应解读为品牌缺席或来源消失。一次变化只属于观察，不宣布某项策略有效。

“本结果测量身份”展示这份结果使用的品牌名、别名及官方域名。修改项目配置不会改写已保存比较；要使用新配置，明确生成新比较。基线和对照覆盖分别展示，不能把一侧计算完整理解为另一侧也已完成。

## 异常处理

| 界面状态 | 应做什么 | 不代表什么 |
| --- | --- | --- |
| 排队，worker 未运行 | 管理员检查健康状态并启动 worker | 模型已经开始执行 |
| 等待调用授权 | 核对本任务范围和有限预算后授权 | 回答分析失败或没有事件 |
| 登录失效、验证码、会话重置失败 | 停止相应采样，人工恢复合法会话 | 可以绕过平台限制 |
| 来源无法获取 | 在高级资料区补录真实正文，或保留限制 | 来源不支持回答 |
| 任务中断 | 读取已保存结果和具体原因，使用恢复未完成步骤 | 应当重采全部历史 Run |
| 用量待核实 | 核实已有请求账单/日志，不重复请求 | 可以把未知费用按零处理 |
| 文本检查未通过 | 查看具体问题、实际修改和复检；保留旧版本 | 空稿也算交付成功 |
| 版本已变化 | 重新读取准确版本，显式选择是否重新分析 | 可以覆盖旧结果或读取任意最新版本 |

“原始资料、人工纠错与高级审计”用于查看精确输入和可选纠错，不是正常用户必须依次完成的审批步骤。Quality Lab 的人工校准与日常自动交付分开。

## 数据与实际执行

项目切换应清除旧项目的页面状态。发现串数据、持续空白或主按钮无响应属于缺陷，不是正常限制。

稿件可以在产品外执行。实际发布、被收录、被引用及指标上涨均不作为软件分析前置；未发生的发布和新采样不得登记为真实结果。私有项目、资料、原回答和未公开稿件不要开放给搜索引擎。
